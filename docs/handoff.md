# 引き継ぎ：fc-counter

最終更新: 2026-11-02（Mac で初版を実装。続きは Windows の配信 PC で行う）

## 今の結論

初版（v0.1.0）の実装は終わった。Mac 上では `dev/server.js`（わんコメの代わり）で動作を確かめ、テストは9件とも通っている。一方、わんコメ本体と OBS では一度も動かしていない。次にやることは、Windows 実機での初回の動作確認である。

## 目的と前提（オーナーと合意済み）

- **主旨**: 配信中に、コメントが今何件来たか、視聴者が何人いるかといった数を、決めた目標に対してどれだけ達成したかとしてリアルタイムに可視化する。
- **参考にしたもの**: BOOTH の「まるっとカウンター」（https://konokakanoko0407.booth.pm/items/9069470 ）。参考に留め、機能・見た目・素材は複製しない。同じフォルダにある `まるっとカウンター_自作要件定義.md` は ChatGPT が書いた要件案で、オーナーの指示により準拠しない。読む価値があるのは、境界値や二重計上の論点だけである。
- **使う人**: オーナー本人の配信だけ。配布や販売はしない。
- **配信環境**: YouTube Live を、Windows の PC から配信する。OBS は入っているが、わんコメはまだ入っていない（2026-11-02 時点）。Mac での動作は考えなくてよい。
- **コメントの取得経路**: わんコメ経由。API キーが要らず、実装も一番簡単だからこれに決めた。
- **数えたいもの**: オーナーの言葉では「有意な数字は全部欲しい、実装コストが高すぎるものは妥協する」。わんコメから取れる範囲で全部を実装し、妥協したものは無い。
- **見た目**: 私（Claude Code）に任されている。実物を見て判断する方針である。
- **技術スタック**: 私に任されている。条件は「簡単に実装できる感じで」。

## 設計で決めたことと理由

| 決めたこと | 理由 |
|---|---|
| わんコメの「プラグイン」に集計と保存をさせ、テンプレートは REST で読む | 表示画面（OBS ブラウザソース）と操作画面（OBS ドック）の間で状態を共有する手段を、OBS 内で確かめられていなかった。プラグインを唯一の状態の持ち主にすれば、共有の問題が消え、表示画面を2枚開いても二重に数えない |
| テンプレートは OneSDK を使わず `fetch` でポーリングする | 集計はプラグインが済ませているため、テンプレートはコメントを受け取る必要がない |
| 目標を越えても周回させず、100% を超えて表示し続ける（例: 120%） | オーナーの主旨は「どれだけ達成したか」で、周回より達成率のほうが直接伝わる。参考品の「満タンで次の杯へ」は採らなかった |
| 達成演出は項目ごとに1回だけ。目標や値を手で書き換えたときは演出を出さない | 同接のように上下する値が目標を何度もまたいでも、演出が繰り返し出ないようにするため |
| スパチャは円建てだけを合計する | 為替換算を持ち込まないため。外貨の扱いは必要になってから決める |
| スパチャはコメントとしても数え、メンバー加入とギフトの通知は数えない | 本文付きのものだけを「コメント」と見なすため |
| 見た目は「丸い器に水がたまる」形にした | 達成率が直感的に分かるため。素材は使わず、CSS と SVG で描いた |

## Mac で確かめた範囲

- 集計ロジックのテスト9件（`npm test`）: 二重計上の防止、連投制限、キーワード、円建てのみのスパチャ、ギフトの件数、同接と高評価、達成演出が1回だけ出ること、0未満にならないこと、項目は10個まで、本文が文字列で届いた場合。
- ヘッドレスの Chrome で撮ったスクリーンショット: 表示画面（6項目の横並び、6桁の数字が器に収まること、達成バッジ）、操作画面（幅600px）、達成演出（帯と紙吹雪）。

## Windows でまず確かめること

上から順に確かめる。どれかで詰まったら、症状を記録してから直す。

1. わんコメを入れて YouTube を登録し、`.\install.ps1` を実行する。そのあと、わんコメのプラグイン一覧に fc-counter が出て、有効にできるかを見る。
   - 出なければ、プラグインの置き場所かファイル構成が違う。わんコメのドキュメントか、公式のサンプルプラグインと照らし合わせる。
2. ブラウザで `http://localhost:11180/api/plugins/fc-counter.local` を開き、JSON が返るかを見る。
   - 形が違う（二重に包まれているなど）場合は、`common.js` の `readJson()` を合わせる。
3. OBS に表示画面（ブラウザソース 1920×1080）と操作画面（カスタムブラウザドック）を登録する。操作画面の「テスト」で偽のイベントを流し、表示画面が動くかを見る。
4. 実際に配信を立てるか、他人の配信を登録して、本物のコメントで数が増えるかを見る。あわせて、同接と高評価の値が入るかを見る。
   - 高評価が入らなければ、`ingestMeta()` で `subscribe('meta')` に届く中身をログに出し、高評価がどの欄にあるかを確かめる。
5. メンバー加入とギフトが数えられるかを見る。本物を待つしかないので、後回しでよい。
